# SellerKit API — первый этап (баланс из YDB)

Этот код **ещё не установлен в Cloud Functions автоматически**.
Нужно перенести `index.mjs` и `package.json` в редактор функции `sellerkit-api`.

## Что уже делает
- Проверяет подпись `Telegram.WebApp.initData` на сервере (HMAC-SHA256).
- Проверяет давность подписи (до 12 часов).
- Подключается к `sellerkit-db` под сервисным аккаунтом `sellerkit-backend`.
- Создаёт запись пользователя с **нулевым балансом** при первом входе.
- Возвращает `{ success: true, balance: 0, ... }` для `POST {action:"me",initData:"..."}`.
- Возвращает безопасный `GET` health check.

## Настройка Yandex Cloud Functions
- Рантайм: Node.js 22, точка входа: `index.handler` (для `index.mjs` может потребоваться `index.handler`; проверить в тестировании).
- При необходимости сменить имя файла на `index.js` в модуле с `"type":"module"`.
- Таймаут минимум 15 секунд, память 256 МБ или выше.
- Сервисный аккаунт `sellerkit-backend`, которому дан `ydb.editor` на **конкретную БД**, а не роли администратора на всё облако.
- Переменные окружения:
  - `YDB_ENDPOINT` = `grpcs://ydb.serverless.yandexcloud.net:2135`
  - `YDB_DATABASE` = путь вида `/ru-central1/.../...`, точно как в YDB
  - `TELEGRAM_BOT_TOKEN` = токен бота (секрет; **не писать в GitHub и не отправлять в чат**).
- Для запросов с GitHub Pages требуется публичный HTTP-вызов функции, но **каждый вызов к балансу проверяет подпись Telegram**.
- Проверить `GET` (здоровье), затем `POST` с реальным `initData` внутри Mini App; не пытаться передавать `initDataUnsafe` как подтверждение личности.

## Чего ещё нет
- Эта версия **не принимает оплату** и **не увеличивает/уменьшает баланс**. Нет метода выдачи кредитов по произвольному запросу.
- Платежи YooKassa (для отдельного сайта) подключаются через проверяемые серверные уведомления.
- Для покупок цифровых генераций **внутри Telegram** требуются Telegram Stars; продажу этих генераций на стороннем сайте из Mini App вместо Stars подключать нельзя.
- Перед запуском для покупателей нужны идемпотентные начисления (таблицы `payments` / `credit_events`), отмены и списания в транзакциях.
- Перед использованием требуется проверить схему таблицы `users` в существующей YDB и развернуть функцию.

## Публичная исходная версия
Только исходный код. В репозитории нет токенов, ключей и реальных данных покупателей.
